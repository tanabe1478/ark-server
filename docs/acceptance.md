# 本番切替の受入確認

自動テスト、A2S、保存ハッシュだけでは、実メンバーのDiscord操作やゲーム内の正しさを証明できません。以下は所有者が実クライアントで確認する具体的な受入項目です。すべてのMOD機能・将来のバージョン・任意の障害を完全に証明するものではありません。

認証情報、guild／Steam ID、Saved、INI、未加工ログを公開issueへ添付しないでください。操作日時・結果と必要最小限の伏せ字済み情報を記録します。

## 切替前の機械確認

- 旧ゲームが実際に停止し、現在Savedが対応する保存後manifestと一致する。
- 旧Savedはread-onlyで取り扱い、独立した新volumeにコピーする。候補Savedを旧環境へ返さない。
- 最新コピーでマップ・人数上限・参加用／管理者用認証・MOD順・倍率・Version初期化を確認する。
- 新環境で非公開の実保存終了と再読込を行う。worldの大幅縮小、profile／tribeの消失を拒否する。
- ゲーム停止中も管理IPCとBotを利用でき、`manager status` が実状態を返す。
- 新旧Botを同時にゲーム操作可能にしない。新Botは受入準備中はofflineにする。

## 実メンバーのDiscord操作

1. 対象guildで `/ark status` を実行し、停止／準備中／readyの区別と警告を確認する。
2. `/ark start` を実行する。ready後に再度startし、同じinvocationのままで起動猶予のみ更新することを機械側で照合する。
3. `/ark restart` の確認画面でキャンセルし、ゲームがそのまま稼働することを確認する。
4. 全員が退出したことを確認し、新しい確認を要求して要求者本人が確認する。クリックは一度だけ有効で、人数が変わった場合は再確認になる。本人が確認した手動restartは実際に保存・切断・再起動を行う。プレイヤー在席や起動直後という理由だけで拒否されるとは考えない。
5. 保存終了確認→新invocation→readyを照合する。3600秒の起動／直近要求猶予は無人時の自動停止の保護で、確認済みの手動restartに1時間待ちを要求するものではない。猶予設定を試験目的で本番だけ短縮しない。
6. 必要なら別メンバーの確認クリック拒否、期限切れ確認も実施する。合成interactionを実ユーザー操作の証拠としない。

## 外部回線からの参加と進行

- サーバーホスト自身ではなく外部回線のARKクライアントで、通常の参加先・既存の参加パスワードを使う。
- 必要なら誤った参加パスワードで1回だけ拒否を確認してから正しいものを使う。パスワードはチャットへ送らない。
- Aquaticaが読込でき、既存キャラクター・tribe・建築・恐竜・主要インベントリ・倍率が想定どおりであることを確認する。
- 既存キャラクターが見つからない場合は新規作成で上書きせず、退出して保全・調査する。
- 退出後の保存終了→同じ現行データでの再起動→再参加で進行を確認する。過去Snapshotの復元をこの確認の代わりにしない。

## MODごとの代表確認（導入している場合）

| MOD | 代表的な確認 |
|---|---|
| Additional Lighting | 対象ライトを表示・設置し、点灯状態を確認 |
| Dino Storage v2 | 価値の低い試験用恐竜で格納・取出し、主要属性を確認 |
| Custom Dino Levels | 設定と新規野生spawnのレベルを確認。1例だけで分布全体が正しいとはしない |
| Super Structures | 試験用建材の設置・接続・操作を確認 |
| Death Helper | 重要な装備を外した安全な試験で死体探索機能を確認。貴重な持物・恐竜を危険にさらさない |
| Ultra Stacks | 試験用資源のスタック・分割・重量表示を確認 |
| Dino Tracker | 所有している試験用恐竜の位置表示・追跡を確認 |
| Awesome SpyGlass! | 対象恐竜の情報表示・主要値を確認 |

確認を終えた項目だけを「確認済み」とします。未確認、失敗、設定依存、試験対象外は分けて記録し、完全互換という一括の判定へ丸めません。
